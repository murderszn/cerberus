CLI Scanner Reference

examine.py is a single Python file that runs the full 58-check catalog in checks.json — the same catalog the web app uses. It is useful for local runs, private repositories, non-GitHub targets, and CI gating.

Usage

python3 examine.py <path-or-github-url> [options]

The target can be a local directory or a GitHub repository URL (with or without .git, /tree/{ref}, or a trailing slash). For a GitHub URL, examine.py resolves the default branch, fetches the file tree, and pulls file contents from the raw.githubusercontent.com CDN. For a local path, it walks the directory directly.

Examples

# Local clone
python3 examine.py ./my-saas-app

# GitHub URL
python3 examine.py https://github.com/owner/repo

Flags

FlagPurpose
--json <file>Write the full report object (schema cerberus.report/2) as JSON.
--html <file>Write a standalone HTML report.
--sarif <file>Write a SARIF file for GitHub code scanning upload.
--fail-under <score>Exit non-zero if the final score is below this threshold. Use this to gate a CI pipeline.
--only <agent,agent,...>Restrict the run to specific agent IDs (e.g. sentinel,vault).
--severity <level>Only report findings at or above the given severity (critical, high, medium, low).

CI / GitHub Actions

Because examine.py has no external dependencies, it drops into any CI runner with Python installed. --fail-under makes the step fail the build; --sarif lets GitHub's code scanning UI show findings inline on the PR.

# .github/workflows/cerberus.yml
name: cerberus
on: [pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.x"
      - name: Run Cerberus
        run: python3 examine.py . --sarif cerberus.sarif --json cerberus.json --fail-under 80
      - name: Upload SARIF
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: cerberus.sarif

The job fails at the --fail-under 80 step whenever the score drops below 80, independent of whether the SARIF upload succeeds — the if: always() on the upload step just ensures findings still show up on a failing run.

Exclusions

examine.py honours the same global_exclude and test_paths globs defined in checks.json, so the CLI and the web app never scan the same noise:

node_modules/, vendor/, .git/, dist/, build/, out/, target/, coverage/,
.next/, .nuxt/, *.min.js, *.min.css, *.bundle.js, *.map,
package-lock.json, yarn.lock, pnpm-lock.yaml, poetry.lock, Cargo.lock,
composer.lock, Gemfile.lock, go.sum, *.snap, __snapshots__/, migrations/

Paths under test/, tests/, spec/, __tests__/, fixtures/, examples/, docs/, and similar are excluded from content-matching checks by default (per-check, via exclude_tests) so fixtures and sample code don't inflate your score.

Output schema

examine.py emits the same Report shape as the web app — see docs/IMPROVEMENTS.md §3.3 for the authoritative schema. In short:

{
  "schema": "cerberus.report/2",
  "target": { "kind": "github", "display": "owner/repo", "sha": "…" },
  "score": 87.5,
  "grade": "B",
  "counts": { "critical": 0, "high": 2, "medium": 5, "low": 3,
              "pass": 46, "fail": 9, "not_applicable": 2, "skipped": 1, "total": 58 },
  "coverage": { "filesInTree": 842, "filesEligible": 310, "filesScanned": 310,
                "filesSkipped": 0, "bytesScanned": 4210233, "truncated": false },
  "agents": [
    { "id": "sentinel", "name": "SENTINEL", "domain": "Code Analysis", "weight": 14, "score": 12.0,
      "checks": [ { "id": "S-01", "status": "fail", "findings": [ { "path": "...", "line": 42, "snippet": "...", "url": "https://github.com/o/r/blob/sha/path#L42" } ] } ] }
  ]
}

Every check in every agent is always present in the output, including passes — the score is not credible without them. See Reading Reports for how to interpret each field.

Limitations

What the scanner does not do

examine.py is a static pattern-matching engine over file content and file presence/absence. It does not execute code, does not perform live CVE database lookups, does not inspect cloud IAM policies or running infrastructure, and does not do dynamic/runtime analysis. Every check's exact detector is documented on the Check Catalog page.
